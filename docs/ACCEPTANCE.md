## 已修复的问题

1. 微型冒烟原先强制串行、忽略并发参数；现在通过 Windows spawn 运行真实作业，并限制在途任务数量，失败后停止派发，在恢复检查点边界退出其他作业。
2. 工程账本原先有累计硬上限且仅在当前进程计数；现在无累计硬上限，子进程独立持久化，锁内汇总，历史字节原样归档，失败预留仍保守保留。
3. 最终预算由崩溃预留补足时，旧代码会报告完成但不提交新的恢复状态；已用失败测试复现并修复。
4. 崩溃前先写出的轻量检查点、最优模型可能领先于持久恢复状态；未提交文件现在归档，最优模型从恢复状态重建，并核验最终模型与恢复模型一致。
5. 完成标记原先不足以发现模型或导出文件被修改／丢失；现在校验实际检查点、预算、原始记录、统计、计时面板和每个资产的哈希。
6. 验收缓存增加工程代码、启动配置、运行环境和并发覆盖；更高并发或不同运行环境使用独立验收目录。正式冻结清单按训练身份比较，运行并发调整不会被误判为算法变化。
7. 继承的 OMP/MKL 线程变量不再覆盖项目配置。Windows 读者短暂占用文件导致的原子替换拒绝已有有界重试和回归测试。
8. 多种子统计输入明确拒绝重复、缺失或不匹配的配对单元；已有种子向量自助区间、效应量与原始 Wilcoxon 协议不变。

故障测试覆盖真实子进程终止、同机进程锁冲突、残留锁恢复、子作业失败后的停止派发与续跑、磁盘不足、文件损坏和缺失资产。异常退出的试验及其交互预留保留在工程账本中。
